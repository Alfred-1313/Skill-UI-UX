# Web panel

The panel is a second door to the same data; it never has settings the bot cannot reach, and
the bot never has settings the panel cannot reach (except things that only make sense in chat).

## Pages that mirror 🎨

- **Texts**: group tabs from the registry, a search box, "only customized" filter, per item a
  textarea with the current text, the default shown beside it, a sticker file_id field, a reset
  link. Language tabs at the top.
- **Paths**: when the bot has paths, the texts and buttons pages get path tabs (one per path
  in the registry, plus "همهٔ مسیرها") under the language tabs; each item says whether it is
  path-only or shared, and has "copy from path" and "apply to all paths".
- **Buttons / looks**: per button group, rows of name / emoji / colour / side / hidden; a live
  preview of the keyboard; drag to reorder; row width.
- **Features**: cards per feature with switches; a feature's settings inside its card.
- **Lists** (users, orders, payments, services): date-range filter with presets (today, 7 days,
  30 days, custom from–to), search, paging, every ID clickable to the profile.

## Behaviour

- Save without a full reload in the normal case (fetch/AJAX), toast "ذخیره شد" only after
  confirmation, the new state drawn at once; a new item appears without a manual refresh.
- Works on a phone: no sideways scroll, touch scrolling inside tables and long lists.
- Right-to-left for Persian, a Persian font (Vazirmatn), numbers formatted.
- The panel's own chrome uses line icons (SVG), not emoji; emoji stay where they are the bot's
  content (a button text the admin set).
- Motion is short and purposeful; respect `prefers-reduced-motion`.
- Log in with a username and password generated by the bot; the bot can reset them.

## Visual direction

Use the builder's `design-profile.md` (bundled in bot-builder-style) for the detailed visual
defaults and evidence. The current direction is «شب»: charcoal, violet accent, floating glass
sidebar, opaque cards with a quiet border. Use SVG outline icons for panel chrome; keep actual
bot emoji/custom emoji in content and previews. Preserve other theme choices and the target
project's identity when requested.

Desktop navigation is grouped, searchable with Ctrl/⌘ K, collapsible and clearly marks the
current page. Mobile gets a drawer and, where useful, a small bottom navigation. Keep the page
title and active location apparent in both. Keyboard focus, accessible control names and
reduced-motion behaviour are part of the component, not a later decoration.

## Saving is a flow, not just an AJAX request

- Preserve scroll, focus, language/path tab, open section and filters. Replace the saved form
  with the server's effective values; update affected lists, counters and previews as well.
  Do not rerun entrance animations on the replaced form.
- Simple safe choices may autosave without a separate button. Text edits keep an explicit save
  action. Show a pending state and serialize/coalesce rapid changes so the final choice wins.
  Treat financial/destructive submissions separately; disabling a button is not idempotency.
- A failure leaves unsaved text available and explains how to retry. An optimistic toggle is
  reverted or clearly marked unsaved if the server rejects it. Never emit a success toast merely
  because fetch resolved; inspect the result and any validation errors.
- A compact toast near the bottom and a brief saved tick give feedback without pushing content
  down. Errors stay available long enough to act on. Do not flood the screen with stacked saves.
- If the response needs another page, the form structure changed, or background update is not
  safe, a reload is acceptable: preserve same-page scroll/filter context and carry the result
  message with it. Expired login sessions lead to login, not a form full of login-page markup.
- Existing authentication, CSRF, authorization and server-side validation apply equally to
  fetch requests. A preview never bypasses these controls or performs a real customer action.

## Phone and Persian details

- Aim for labelled row cards on narrow management lists. Wide layout editors can scroll inside
  their own wrapper; a finger on a row must still scroll the page vertically. Never widen the
  entire document to fit a table. Keep labels when hiding secondary columns.
- Stack form columns, use bottom-sheet dialogs when appropriate, allow safe-area space below
  fixed navigation, and make controls comfortable to tap. Touch input text is at least 16px.
- Persian UI uses Vazirmatn, RTL and no letter spacing on joined letters. Use tabular digits
  for numeric comparisons and isolate handles/IDs/URLs as LTR without changing copied values.
- Date range, search, status, language and sort compose in one bookmarkable URL, with paging.
  Offer useful presets and optional from/to ends. Calendar preference can be remembered;
  displayed boundaries and queries use the same product timezone. Reset paging when filters change.
